# 자바 스터디 운영 가이드

세션(채팅)끼리는 서로 대화 내용을 기억하지 못하므로, **이 저장소의 문서가 유일한 공유 기억**이다.
모든 세션은 시작할 때 문서를 읽고, 끝날 때 문서를 갱신한다.

## 정본과 동기화 (2026-11-25부터)
- **정본 = GitHub 비공개 저장소 `sang-mil/java-study`의 `main` 브랜치.** Claude 프로젝트 「자바 스터디」의 문서는 2026-11-25 이전 사본이며 더 이상 갱신하지 않는다.
- **Claude 세션**: GitHub 커넥터로 `sang-mil/java-study`의 파일을 읽고(`get_file_contents`) 쓴다(`create_or_update_file`, 기존 파일은 최신 sha 필요). 쓰기 직전에 파일을 다시 읽어 최신 내용에 덧붙인다.
- **Codex(로컬)**: 세션 시작 전 `git pull`, "종료" 때 바뀐 파일만 커밋하고 `git push`. 자세한 규칙은 저장소 맨 위 `AGENTS.md`.
- **동시에 두 도구에서 같은 세션을 돌리지 않는다.** 한쪽에서 "종료"로 push한 뒤 다른 쪽을 시작한다.
- 커밋 메시지 형식: `[세션] 한 줄 요약` 예) `[시험] Part1 재시험 기록`, `[운영] 6장 지시`.

## 세션 구성 — 모두 고정 채팅(상주)
| 세션 | 성격 | 채팅 |
|---|---|---|
| **운영** | 체계 전체를 관리. 매 강의·시험 사이에 들러 다음 지시를 쓴다 | 고정 채팅 1개 |
| 강의 | 회차 학습 | 고정 채팅 1개 |
| 질문 | 자유 질문 | 고정 채팅 1개 |
| 시험 | 평가 | 고정 채팅 1개 |
| 블로그 | 시험 통과한 장을 글로 정리·게시 | 고정 채팅 1개 |

어느 세션이든 Claude 채팅이나 Codex 중 편한 곳에서 돌릴 수 있다. 채팅이 너무 길어져 느려지면 새 채팅을 열고 `05_세션프롬프트.md`의 [상주 설정] 메시지를 한 번 붙여 넣는다.

## 지시 전달 방식 (운영 → 각 세션)
세션끼리는 직접 메시지를 주고받을 수 없으므로 **`08_세션지시.md`가 우편함** 역할을 한다.
1. 운영 세션이 `08_세션지시.md`의 해당 세션 항목에 지시를 쓰고 상태를 `대기`로 둔다.
2. 학습자가 그 세션 채팅에 **"지시 확인"**이라고만 입력한다.
3. 세션은 `08_세션지시.md`에서 자기 항목을 읽고 `진행 중`으로 바꾼 뒤 수행한다.
4. 끝나면(학습자가 "종료") 가이드대로 문서를 갱신하고, 지시서 항목을 `완료` + 결과 한 줄로 바꾼다.
5. 학습자가 운영 세션에 "끝"이라고 하면 운영이 점검 후 다음 지시를 쓴다.

## 학습 루프
```
운영(지시) → 강의 → 운영(점검·지시) → 시험 → 운영 → 블로그(통과 시) → 운영 → 강의 → …
                     ↘ 질문 (필요할 때 언제든) ↗
```

### Codex 단일 세션
Codex에서는 운영·강의·질문·시험·블로그를 하나의 연속된 채팅 안에서 진행한다. 역할 태그와 지시서는 작업 흐름을 표시하는 용도로만 쓰며, 학습자에게 채팅을 나누거나 옮기게 하지 않는다. assistant가 현재 진도와 운영 규칙을 보고 다음 역할을 정해 진행하고, 결과는 이 저장소 문서에 기록한다. Claude의 고정 채팅 방식은 그대로 둔다.

## 0. 운영 세션
학습자가 다른 세션을 마치고 돌아오면 아래를 수행한다.

**점검 (매번)**
1. 모든 문서를 읽고, 직전 세션이 문서와 지시서를 제대로 갱신했는지 확인한다. (저장소 최근 커밋도 확인)
   - 누락·모순(예: 강의는 했는데 진도 미기록, 시험 오답이 약점노트에 없음)을 찾으면 학습자에게 확인 후 보정한다.
   - 학습자가 직전 세션 결과를 말로 전해주면 그것을 기준으로 반영한다.
2. 현황 보고 (짧게)
   - 진도: 완료 회차 수 / 전체, 현재 위치
   - 오늘·지난 복습 대상 회차
   - 약점: 🔴 n개, 🟨 n개, 최근 해결
   - 최근 시험 점수 추이
   - 블로그: 게시한 글 수, 글로 정리할 차례인 장
3. **다음 행동을 결정**하고 `08_세션지시.md`에 지시를 쓴 뒤, 학습자에게 "어느 채팅에 '지시 확인'"인지 알려준다.

**다음 행동 결정 규칙 (기본값, 운영 중 조정 가능)**
- 복습일이 지난 회차가 3개 이상 쌓였거나 🔴 약점이 5개 이상 → **시험**
- 직전 강의 후 시험을 아직 안 봤으면 → **시험** (강의 직후 또는 다음 날)
- 최근 시험 70% 미만 → 해당 범위 **재강의 또는 질문 세션** 후 재시험
- 한 장의 시험을 70% 이상 통과했고 아직 글이 없음 → **블로그** (다음 강의 전에)
- 최근 시험 70% 이상이고 복습 밀린 것 없음 → **다음 강의** (한 번에 한 장 또는 4~6회차)
- 같은 약점 오답 3회 이상 → 별도 **질문 세션**으로 집중 처리

**주간 회고 (7일마다 또는 요청 시)**
- 지난 주 학습량, 점수 추이, 반복되는 약점 유형, 블로그 게시 수를 정리
- 규칙(출제 비율, 복습 간격, 강의 분량)이 맞지 않으면 개선안을 제안하고, 합의하면 가이드·프롬프트를 수정
- 결과를 `06_운영로그.md`에 기록

## 1. 강의 세션 — "영상 먼저 → 튜터 정리"
**시작:** `08_세션지시` [강의] 항목, `01_진도`, `02_약점노트`를 읽는다 → 오늘 복습할 회차가 있거나 미해결 약점이 있으면 5분 정도 복습을 먼저 한다.
**진행 (회차마다):**
1. **시청 안내** — 회차 번호·제목·길이, 집중할 포인트 2~3개를 주고 멈춘다.
2. 학습자가 영상을 보고 와서 **'봤음'**(+ 메모)이라고 하면:
   - 먼저 학습자에게 한 줄 요약을 시킨다 (인출 연습)
   - 핵심 개념 3~5개 정리, 빠졌거나 틀린 부분 보충(영상 밖 내용은 "보충" 표시)
   - 구조·흐름·메모리 개념은 구조도를 직접 그려서 설명
   - 짧은 예제 코드 (해당되는 회차만)
3. **'못 봄'**이면 튜터가 주제 기준으로 처음부터 가르친다 (진도표에 "영상 미시청" 표시).
4. 확인 질문 1개 → 채점 → 이해도(1~5, **튜터가 근거와 함께 평가**) → 다음 회차 시청 안내.
**종료:**
- `notes/`에 장별 노트 저장 또는 추가 (구조도는 텍스트/Mermaid로 함께)
- `01_진도`에 상태 ✅, 강의일, 이해도, 복습 예정일 기록 (미시청 회차는 표시)
- 확인 질문에서 틀린 개념은 `02_약점노트`에 추가
- `08_세션지시` [강의] → `완료` + 결과 한 줄

## 2. 질문 세션
**시작:** `01_진도`, `notes/`를 읽고 학습자가 어디까지 배웠는지 파악한다 (아직 안 배운 내용으로 답하지 않고, 필요하면 "Part X Y에서 다룸"이라고 알린다). 지시서에 [질문] 지시가 있으면 그것부터.
**진행:** 자유 질문. 개념을 다시 짚을 때는 해당 회차를 표시한다.
**종료:**
- `03_질문노트`에 질문 / 답 요약 / 관련 회차 기록
- 질문에서 오개념이 드러나면 `02_약점노트`에 추가
- 질문으로 해결된 약점은 상태를 🟨(확인 중)으로 변경
- 지시가 있었으면 `08_세션지시` [질문] → `완료`

## 3. 시험 세션
**시작:** `08_세션지시` [시험] 항목, `01_진도`(✅ 회차만 출제), `02_약점노트`, `04_시험기록`을 읽는다.
**출제 비율 (기본 10문항):**
- 약점노트의 미해결·확인 중 개념: 40%
- 복습 예정일이 지났거나 오늘인 회차: 30%
- 그 외 완료 회차: 30%
- 문항 유형을 섞는다: 개념 회상 / 이해(왜?) / 적용(코드 읽기·결과 예측·버그 찾기). 학습자는 숫자 암기형보다 **설명형**을 선호한다.
**진행:** 한 문항씩 출제하고, 정답은 학습자가 답한 뒤에 공개한다.
**종료:**
- `04_시험기록`에 날짜, 범위, 점수, 틀린 문항과 이유 기록
- 틀린 개념 → `02_약점노트`에 추가하거나 오답 횟수 +1
- 약점 개념을 2회 연속 맞히면 상태 ✅(해결)
- `01_진도`의 복습 예정일 갱신 (맞힘 → 다음 간격, 틀림 → 1일 뒤로 리셋)
- `08_세션지시` [시험] → `완료` + 점수

## 4. 블로그 세션
**블로그:** https://sang-mil.github.io (저장소 `sang-mil/sang-mil.github.io`, Jekyll Chirpy 테마, main에 push하면 GitHub Actions가 자동 배포)
**게시 조건:** 범위의 회차가 모두 ✅ + 해당 범위 시험 70% 이상. 글 단위는 기본 1장 = 1편.
**소재:** `notes/`, `02_약점노트`, `03_질문노트`, `04_시험기록`만 쓴다. 영상 내용을 옮겨 적지 않고 출처 링크를 단다.
**구성:** 들어가며 → 회차별 핵심 개념(구조도는 Mermaid, `09_블로그그림스타일.md` 규칙) → 예제 코드 → 내가 헷갈렸던 것 → 정리 3줄 → 출처
**진행:** 초안을 대화에 보여주고 수정 → 학습자가 **"게시"**라고 해야 push → 배포 후 글 주소 안내.
**종료:** `07_블로그기록`에 게시일·범위·제목·주소 기록, `08_세션지시` [블로그] → `완료`.

## 복습 간격 (간격 반복)
강의 후 **1일 → 3일 → 7일 → 14일 → 30일**. 시험에서 맞히면 다음 간격으로 넘어가고, 틀리면 1일부터 다시 시작한다.
